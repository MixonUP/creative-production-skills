# Проверить красоту, точность и поведение в игре

## Два сравнения и три набора данных

**Контролируемый A/B** меняет только интересующий фактор: reference, adapter, decoder или одну настройку. **Сравнение готовых профилей** позволяет каждому кандидату свои проверенные настройки; сохранить их рядом с WAV. SECourses по умолчанию может оценивать candidate deployment settings, поэтому Base и adapter могут отличаться не только весами. Для причинного утверждения нужен первый тип; для выбора слышимого результата полезен второй.

Train обучает, validation выбирает, test подтверждает заранее замороженный выбор. Предлагаемый компактный benchmark в `assets/benchmark.jsonl` — новые игровые тексты для baseline и smoke listening, **не** приватный независимый тест и не материал для обучения. После настройки на нём нужен новый резерв. Русские строки предназначены для поддерживающей RU модели, а не служат обещанием RU у IndexTTS.

До проверки сохранить reference hashes, target text, language, seed, model revision, adapter/decoder hashes/strengths, generation settings, processing и состояние GPU. Предлагаемый бюджет для короткого сравнения — 12–24 разных реплик ×3 seeds; на пилоте допустимо меньше с явной пометкой низкого покрытия. Несколько seeds одной фразы не являются независимыми репликами. Для неопределённости группировать по prompt, а лучше по записи/сессии, когда их достаточно.

## Что мерить

| Критерий | Полезное свидетельство | Что оно не доказывает |
|---|---|---|
| Произношение | WER/CER, ручная сверка имён, чисел, отрицаний, первого/последнего слова | ASR ошибается; punctuation/case normalization не должно скрывать содержательную ошибку |
| Идентичность | Speaker similarity к нескольким реальным held-out clips; слушатель узнаёт персонажа | Высокая similarity не означает приятный звук или правильное исполнение |
| Естественность | Слепое сравнение, отсутствие металлических призвуков, разрывов и бессмысленных пауз | Token loss и embedding не заменяют слух |
| Актёрская подача | Слышно нужное намерение при сохранённом тембре | Сильнее эмоция не всегда лучше |
| Устойчивость | Новые темы, короткие и длинные реплики, серия диалогов, разные seeds/references | Одна удачная генерация не покрывает хвост ошибок |
| Игровой runtime | Time to first audible sample, полная latency, p50/p95 при достаточном N, RTF, очередь/отмена, VRAM | Время одного тёплого TTS не равно отзывчивости всей игры |

Измерять ASR и на настоящих записях, чтобы видеть ошибку распознавателя. Сохранять ошибочные дубли; не отбирать только удачные WAV. Метрики указывать с объёмом выборки. Наши ранее измеренные 2.91 с IndexTTS на 4.03 с EN-аудио — одна тёплая проба, не p95 и не качество тренированной LoRA.

## Слепое прослушивание

Использовать авторский `listening_review.html` либо обезличенные A/B-файлы с отдельным ключом соответствия. Выровнять громкость **копий**; порядок рандомизировать. До раскрытия кандидата оценить 1–5: разборчивость, тембр, естественность, соответствие образу/эмоции, усталость от длительного слушания. CSV-шаблон в assets. Пустая оценка означает «не слушали», а не ноль.

Один человек может провести полезный рабочий отбор; не называть его формальным MOS-исследованием. Оценки аудиомодели хранить отдельно как вспомогательные и обозначать модель/промпт/доступность имён кандидатов. Не заявлять «я прослушал», если был только ASR или изображение волны. Пользовательский выбор художественного голоса имеет приоритет над небольшой разницей автоматического score.

Практические gates проекта (это наши критерии, не закон модели): не принимать потерю смыслового «не», неправильный пароль/число, обрезанное окончание или смену говорящего в обязательных строках; при близком качестве выбрать стабильный и более быстрый профиль. Для фоновых/динамических реплик определить допустимую частоту некритичных ошибок отдельно от сюжетных фраз. Озвученные заранее важные реплики — возможная страховка, не скрытая подмена теста генерации.

## Диагностика по симптому

| Симптом | Следующее действие |
|---|---|
| Пропуск последнего слова | Сверить края обучающих клипов, token budget/segmentation, checkpoint/version; сравнить Base; не тянуть конец time-stretch |
| Тембр похож, речь странная | Отдельно decoder off/on; проверить язык, transcript, реальный reference и strength |
| Тонкий/шипящий голос | Сравнить сухой output, reference, decoder strength и обработку; не начинать с добавления высоких частот EQ |
| Много пауз/междометий | Просмотреть соответствующий training material и fluency-фильтр; не вырезать все естественные паузы |
| Эмоции меняют личность | Снизить интенсивность, взять same-speaker emotion reference, зафиксировать identity reference |
| Train loss падает, новые фразы хуже | Откатить checkpoint, проверить leakage/разнообразие и переобучение; увеличить данные по дефекту, а не эпохи автоматически |
| Красиво, но задержка велика | Сравнить меньшее число candidates/beams/steps, длину сегментов, кэш и бюджет совместно с LLM; повторно принять качество |
| Все NPC звучат одинаково | Пересмотреть cast cards и фактическое назначение reference/adapter; не просто поднять pitch каждому |

## Передача в игру

Сохранить отдельный versioned bundle на `voice_id`: provider + base revision, language, identity reference, разрешённые emotion profiles, adapter/decoder + hashes, strengths, segmentation, pronunciation dictionary, speaking-rate calibration, normalisation policy и доказательства. Cache key должен включать voice version, text/language/emotion и профиль генерации, иначе после смены голоса останется старый звук.

В текущем RnD игра читает один `voice-profile.json`; settings проходят в author generation request. Проверенные имена: `runtime.lora_path`, `runtime.lora_strength`, `runtime.lora_merge_into_base`, `runtime.decoder_adapter`, `runtime.decoder_adapter_strength`. Использовать абсолютный adapter path, потому что рабочая директория игры и Vendor могут различаться. Наличие ключей ещё не доказывает, что новый adapter загружен: после изменения перезапустить RnD и проверить выбранные файлы, лог/metadata и A/B. Автонастройки Studio и game profile не синхронизированы.

DoRA/GPT и decoder weights сохранять раздельно, вместе с metadata. Сохранить явный возврат к baseline; merge не выполнять поверх единственной базовой модели. Для многих NPC проектировать очередь/кэш адаптеров с профилем на персонажа, ограничением памяти и отменой устаревшей реплики. Сейчас такая система не реализована: не описывать шаблон bundle как работающий менеджер.

После подключения проверить русский STT (если нужен), reply language, playback, паузы/жест, прерывание, отмену при смене NPC/сцены, повторную загрузку голоса и session isolation. Mouth amplitude/жест не означает фонемный lip sync. Сначала RnD, потом принятый пользователем перенос в Main. Модели и аудио не добавлять в Git по привычке.
