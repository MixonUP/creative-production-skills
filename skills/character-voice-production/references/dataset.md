# Датасет: содержание важнее часов

Применять к новому голосу или исправлению устойчивого дефекта. Авторские технические значения ниже проверены в локальном `indextts/training/dataset_prep.py` на commit `a776268d8c532e19836a1fa90f4e8d28b9ea20fe`; это defaults этой версии, не универсальные нормы.

## Хранение и разделение

Сохранять неизменяемые оригиналы, происхождение и область разрешённого использования. Предлагаемая структура отдельного опыта: `raw/`, `prepared-v001/`, `references/`, `plans/`, `runs/`, `evaluation/`, `selected/`. Папку создавать внутри RnD либо указанного пользователем проекта; адаптеры автора могут оставаться в штатном `Vendor/SECourses/loras` с явной ссылкой из опыта.

Делить по исходной записи/сессии **до** нарезки, а не случайно разбрасывать соседние фрагменты одного файла. Для независимого финального теста сохранить ещё одну сессию. Название файла не защищает от утечки: копия с другим именем, другой контейнер или перекодирование остаются той же записью. Если материал — одна длинная запись, автоматическое разбиение по клипам даёт только ограниченную проверку внутри сессии; не заявлять межсессионную устойчивость.

Training references должны происходить из обучающей части, а не из финальных тестовых targets. В SECourses режим speaker reference `other` исключает текущий target и использует того же говорящего. Для Qwen SFT контракт иной: официальный пример рекомендует общий ref_audio. Не переносить правило случайного декодерного prompt на все провайдеры.

## Подготовка SECourses

1. В **LoRA Dataset Preparation** указать медиа и проверенные sidecar-транскрипты, новый output name, один speaker. Начать с ограниченного числа клипов для осмотра. Не использовать overwrite для исправления уже обученного датасета.
2. Предпочесть sentence-aligned нарезку с целыми словами и паузами; субтитры — черновик, который ещё надо сверить с произнесённым. Неточные подписи не становятся правильными от forced alignment. Имена, числа, сокращения, первые и последние слова проверять особенно внимательно.
3. Defaults этой версии: моно 24 kHz; диапазон 4–16 с; целевая длина 14 с с долями коротких и средних клипов по 0.25; padding 60 мс; -20 LUFS; clipping ratio ≤0.001 при пороге 0.999. Это формат обучающей подготовки. Выход модели 22.05 kHz — другой этап. Не менять один под другой.
4. Короткие игровые «Да», «Стой» и «Нет» обязательно включить в **оценку**. Для обучения авторские min_s/min_words могут их отфильтровать: не ломать defaults без отдельного опыта и не склеивать разные сессии, чтобы пройти длину. Нужны полные естественные контексты и осмысленная вариативность длины.
5. Проверить принятую и отвергнутую выборки: обрезанные окончания, неправильно разделённые реплики, второй голос, музыка, чрезмерная тишина, реверберация, шумодав. Ошибки переписать/перенарезать; громкостью их не лечить.
6. **Voice and transcript audit** помогает найти несоответствия speaker/text. **Training data fluency → Analyze dataset** показывает, сколько материала сохраняют фильтры. Для персонажа с естественными запинками не выбирать Strictly fluent автоматически. В этой версии fluency-фильтр меняет train, сохраняя val; всё равно записать итоговый manifest.
7. После окончательных правок сделать feature cache. Изменение звука, текста, базовых моделей или extraction settings требует обновления и проверки cache fingerprint. Не использовать «старый cache, новый manifest» как один датасет. Кэширование может загрузить GPU/ASR, поэтому входит в разрешение на вычисление, а не в чтение файлов.

Покрытие важнее механической балансировки: фонемы языка, мягкость/твёрдость и окончания в русском, имена/топонимы мира, вопросы, повествование, повелительные реплики, умеренные эмоции, темп. Не смешивать несколько актёров под одним speaker ID и не рассчитывать, что LoRA усреднит их в устойчивую новую личность.

## Локальный аудит без моделей

`scripts/audit_manifest.py` читает JSONL автора (поля `audio`, `text`, `source_media`, `speaker`, `language`, `duration_s`, `id`) и отдельную карту `id → train/val/test`, если в строках ещё нет split. Относительный audio разрешается от папки его manifest. Можно передать несколько `--manifest` с уникальными ID. До сохранённого разбиения получится `NEEDS_SPLIT`, а не ложный PASS. Аудитор не повторяет собственный splitter тренера: карту следует выгрузить из фактического плана/выбранных записей.

Пример в PowerShell из папки навыка, все пути к пользовательским данным задаются явно:

```powershell
& 'E:/Krea_tren_AI/GamesDev/RnD/IndexTTS/.venv/Scripts/python.exe' './scripts/audit_manifest.py' --manifest 'E:/voice-lab/prepared/manifest.jsonl' --split-map 'E:/voice-lab/plans/splits.json' --output 'E:/voice-lab/evaluation/audit.json'
```

Пути `E:/voice-lab` — пример, не установленный проект. Скрипт использует уже имеющиеся numpy/soundfile, не запускает модели и не меняет аудио. Проверяет читаемость, finite samples, длительность, частоту/каналы, sample peak, DC, долю почти насыщенных samples, SHA256 файлов и декодированного PCM, дубликаты и пересечение source/session между split. Ошибки — exit 2; неполнота/сигналы для ручного осмотра — exit 1; техническая проверка без замечаний — exit 0. Последнее не означает художественную приёмку.

Он не измеряет LUFS, истинный SNR, true peak, качество транскрипции, говорящего, права и фазовые артефакты; не находит надёжно перекодированные/подрезанные копии. Source/session IDs должны быть достоверными. Сохранять аудиторский отчёт и исходный manifest с хешем в snapshot; существование нынешнего manifest не доказывает, что именно он использовался прошлым запуском.
