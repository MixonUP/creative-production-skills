# Reference → property → experiment

Use a short ledger for consequential references:
ID; URL/path; exact excerpt/region; actually inspected modality; relevant property;
proposed implementation; property to preserve; deliberately different property;
usage permission; test; verdict and evidence.

For sound describe attack, body, tail, pitch trajectory, harmonic/noise content,
rhythmic density, dynamic range and spatial perspective. For music add phrasing,
motif development, harmony, tempo and instrumental roles. An artist/game title is
a starting reference, not the implementation brief.

Choose a useful contrast: metal versus wood, light versus heavy, low versus high
energy. Compare one meaningful change while holding the event, duration and mix
context stable. Differentiate faithful reference analysis from a new creative proposal.

## Audition loop

1. Select a cue, its action anchor and the reference property being tested.
2. Render a few meaningfully different variants with stable IDs and seeds.
3. Present them without overlapping narration or simultaneous playback.
4. Inspect isolated sound, repeated use and representative picture/gameplay context.
5. Record chosen take, reason, remaining defect and one next edit.
6. Keep the rejected recipe and source; do not silently replace a selected take.

A technical defect can reject a candidate before listening. Passing technical checks
cannot select it aesthetically. A source video with commentary over effects can
support observations about the workflow but is a poor isolated listening reference.

## Tool loop

Choose the route per operation: deterministic script for a reproducible batch, an
existing MCP/API for supported scene operations, native UI for a necessary inspection.
Inspect capabilities and target identity first. Give the tool the smallest coherent
operation, read back the actual result, inspect the artifact, then make a targeted edit.
A tool's success response is not evidence of its sound or appearance.

Retain enough before-state for a focused rollback. Use one writer for a live scene.
Keep reference analysis and provider-specific syntax separate. A new service or plugin
is not required when an existing script or API can complete the operation.
