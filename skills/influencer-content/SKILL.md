# Content that has a production route

Adapted from Tilbury's content-engine; source audit: E:/Krea_tren_AI/Knowledge/06_Sources/Tilbury_Skills_Adaptation_2026-09-23.md. Read the specified character bible and current brief. Carry character_id and content_id into every production handoff.

Route to the requested stage: ideas only, an existing topic's script, or complete ideas-to-scripts. When the user delegates selection, select a defensible set and write it; don't insert the source's mandatory STOP. Ask only when missing character/audience/language or another real dependency prevents useful work. Use known preferences and label assumptions.

For current trends or factual claims research primary sources and retain URLs/dates. Distinguish observed account data from a hypothesis about why something works. Evergreen fiction can be drafted without an arbitrary number of searches. Don't invent statistics, testimonials, credentials or personal experience as real evidence. Persona fiction stays identifiable as fiction.

## Prepare the batch

- Each idea has an audience need, hook, promised payoff, format, setting, required inputs, production difficulty and intended metric. Count/length follow the request; a small pilot can use three recurring formats rather than eight mandatory ideas.
- Write spoken text separately from captions, acting and technical instructions. Keep the selected narration language intact. Estimate duration from the intended voice/language; replace estimates with measured audio length before video submission.
- Use the character's vocabulary and rhythm. Pauses, restarts and anecdotes are optional expressive choices, not compulsory artificial errors. Let the hook's promise resolve in the script. A CTA is optional when it helps the piece.
- Offer alternate openings when testing hooks. Keep other major variables stable enough to interpret the test; record publication age when comparing metrics.
- Match complexity to the route: static talking head, silent b-roll plus overlay, voiceover montage, demonstration or staged interaction. Simple formats are a cost-saving default, not a ban on screen recordings, products or multiple characters. Complex beats need an appropriate shot plan and acceptance test.

Product fit must not suppress true material limitations or contradictory evidence. Verify consequential health/financial claims using appropriate primary sources; don't let a fictional persona imply professional credentials. Avoid promises of growth, revenue or platform approval.

Return reviewable content cards: IDs, title, hook/caption, clean script, voice version, estimated/measured duration, shot needs, factual sources where relevant, optional CTA and test hypothesis. Store technical generation settings in the shot manifest rather than mixing them into the script.
