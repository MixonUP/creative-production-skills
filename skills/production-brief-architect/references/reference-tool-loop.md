# Reference-led work with observable tool results

Use when the user supplies examples or asks to transfer a workflow. Keep this narrow:
one asset or cue does not require a whole production management system.

## Build the reference packet

For each useful source record ID, exact excerpt/image region, inspected modality,
property to transfer, why it matters, implementation hypothesis, deliberate differences
and the test that can accept or reject the transfer. Preserve source usage restrictions.
Separate artwork/music references from technical references describing how to build it.

Examples:
- A robot image can constrain silhouette, mass distribution and joint clearance; it
  does not reveal an original rig or exact dimensions. Test silhouette and articulation
  from the intended camera before adding detail.
- A sound excerpt can guide attack, pitch fall, resonant body and tail. Choose an
  excitation/envelope/filter recipe or recording/model route, then audition it.
- A music reference can guide density, phrasing and the relationship of layers while
  retaining an original motif. Mark BPM/key as observed, measured or proposed.
- A film reference can guide screen direction, blocking, timing and sound perspective;
  unknown camera metadata stays estimated.

If sources conflict, assign them different roles or choose which property has priority.
Do not combine every reference indiscriminately. A short inspectable evidence packet
is better than a list of names the next agent cannot translate into decisions.

## Write a tool-operation contract

For each consequential operation describe target identity, minimal input, required
capability, expected artifact, readback and review. Match the route to the task:
- existing script/CLI for deterministic batches and reproducible revisions;
- existing MCP/API for supported editor/scene changes;
- native UI for inspection or an operation without a usable API.

Inspect the real session/project and current capability before mutating it. Save the
specific before-state needed for rollback. Perform one meaningful step, read back
actual output, inspect pixels/sound/behavior and make a targeted correction. Successful
tool calls and attractive review pages are not proof of an accepted production result.
Keep one writer per live editor and leave parallel agents to separately authorized work.

## Prove a representative chain

Specify a test preserving the defining experience: one reference-based prop reaches
the real scene; one audio cue reaches its real contact or picture event; one shot fits
the edit and preserves state into the next. Review before multiplying the library.

For sound, distinguish procedural synthesis, recorded/licensed Foley, neural music/SFX
and hybrid treatment. Code generation writes a synthesis program; the program creates
audio. Model-based audio directly invokes an audio model. These have different controls
and failure modes; no route is mandatory merely because a comparison video used it.

Deliver a human-reviewable contact sheet, audition page or small scene where useful,
with stable IDs and explicit decisions. Ask for taste only after concrete candidates
exist. Exact source code or creator skills unavailable in a video remain unavailable;
label a local reconstruction as our implementation.
