# Review the brief as an executable document

Use this review on the completed proposal; fix concrete faults before presenting it.
Do not inflate a document to satisfy a word count.

## Traceability

For each P0 requirement identify its source/status, implementing system or shot,
dependencies, milestone and evidence. Nothing critical should exist only in a kickoff
sentence. Conversely, every expensive proposed system/shot should serve a declared
experience or required delivery.

## Coherence checks

- Do gameplay promises and video promises agree with scope, resources and deadlines?
- Is one system authoritative for each state, event and movement axis?
- Are normal, cancelled and interrupted actions specified where they change results?
- Does the proposed first slice actually test the distinguishing experience?
- Are asset/cast quantities consistent between story, matrix and milestones?
- Are references observations, borrowed properties or approved designs clearly separated?
- Does a shot's first state permit its last state and its successor's first state?
- Do dialogue, action and edit intervals fit without undocumented retiming or assistance?
- Is screen direction maintained or intentionally changed?
- Are all supposed tools, model modes and APIs actually available or explicitly unverified?
- Does any proposed workflow contradict project version locks or source preservation?

## Evidence discipline

A criterion should be observable and attributable. "Professional, cinematic, AAA, 10/10"
is not an acceptance test. Replace it with visible behaviors/properties and an appropriate
review method. Avoid false precision: do not invent source measurements or guarantee
perception by a numerical score.

Separate implementation correctness, technical output quality, artistic judgement and
user acceptance. Use not-run for planned tests. Mark debug assistance, offline renders
and provider simulations so they cannot stand in for ordinary runtime/output evidence.

## Failure rehearsal

Walk through the actual proposal with these questions:
1. Does the core action or emotional beat still work if the prettiest asset is absent?
2. What happens if the action is cancelled, a generation fails or an input is missing?
3. Can another agent locate the next step after interruption without re-reading everything?
4. Which assumption, if wrong, forces the largest rework? Test it before expanding.
5. What will the final handoff prove, and what will remain a judgement?

Return only consequential open issues. Prefer a concrete recommended resolution over
a long question list. Do not silently delete a difficult P0 or invent approval.
State readiness as ready to execute, ready with named assumptions, or blocked on
specific decisions/dependencies. A blocked expensive step need not block independent
planning or a reversible prototype.

## Compression pass

Remove duplicated rules, generic expert-role theatrics and disconnected feature lists.
Keep rationale where it controls tradeoffs. Move large specialised material to linked
sections/files if that helps execution. Preserve critical constraints in KICKOFF so
a fresh agent cannot miss them. Leave a clear completion condition rather than an
instruction to work forever.
