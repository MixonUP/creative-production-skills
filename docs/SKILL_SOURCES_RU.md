# Где искать сильные навыки и как выбирать

**Проверено 7 октября 2026.** Универсального доказанного рейтинга «лучшие в мире»
не обнаружено. Ниже — первичные источники и кандидаты с понятным назначением.
Исследованы их публичные описания и состав; новые пакеты этим действием не установлены
и на наших производственных задачах не протестированы.

## Основные источники

| Источник | Чем полезен | Приоритет для нашей библиотеки |
|---|---|---|
| [OpenAI Plugins](https://github.com/openai/plugins) | Актуальные примеры пакетов для Codex, сочетающих навыки и инструменты | Первый источник для совместимости с Codex; смотреть текущие интеграции и структуру пакетов |
| [Anthropic Skills](https://github.com/anthropics/skills) | Примеры творческих и технических навыков, MCP и проверки веб-приложений | Изучить mcp-builder, webapp-testing, algorithmic-art; исключать дубли уже имеющихся возможностей |
| [Remotion Agent Skills](https://github.com/remotion-dev/skills) | Навыки для программного видео, титров, субтитров и управления композицией | Сильный кандидат на пробел точной графики и серийных роликов; это отдельная технология, не замена всей киноцепочки |
| [Vercel Agent Skills](https://github.com/vercel-labs/agent-skills) | Рекомендации по React/Next.js, производительности и проверке веб-интерфейса | Полезно для витрин, инструментов студии и браузерных интерфейсов; прямой пользы для Godot может не быть |
| [Superpowers](https://github.com/obra/superpowers) | Связанный процесс разработки, отладки, тестирования и ревью | Изучить systematic-debugging и verification-before-completion; переносить совместимые части после проверки |
| [Skills.sh](https://skills.sh/) | Широкий поиск пакетов, авторов и популярных направлений | Использовать для обнаружения кандидатов; дальше читать исходный репозиторий и проверять на своей задаче |
| [Agent Skills specification](https://agentskills.io/specification) | Формат SKILL.md, метаданные и структура пакета | Основа для проверки совместимости; это стандарт, не каталог лучших результатов |

### Важные уточнения

Старый [openai/skills](https://github.com/openai/skills) явно помечен deprecated и
направляет в `openai/plugins`. Его нельзя представлять как главный актуальный
каталог без этой оговорки. В новом каталоге есть, в частности, примеры Figma,
веб-приложений и Remotion. [Текущий README](https://github.com/openai/plugins).

У Anthropic лицензии неоднородны: README отличает многие открытые примеры от
source-available документных навыков. Проверять условия нужно в выбранном компоненте.
Нам уже доступны документные плагины, поэтому копирование нового документного
набора не является первым приоритетом. [Описание и лицензирование](https://github.com/anthropics/skills).

Remotion поддерживает отдельные навыки создания, разметки, рендера, субтитров и
картографической анимации. Проверять стоит на типографическом или информационном
ролике с точными временем и текстом. Это рекомендация по соответствию задаче,
а не утверждение о превосходстве в художественном кино. [Официальное руководство](https://www.remotion.dev/docs/ai/skills).

В Superpowers есть обязательные процессы, автоматические триггеры и специфические
правила разработки. Их нельзя переносить поверх текущих инструкций без проверки
конфликтов: например, принудительные подтверждения каждого дизайна и подход к TDD
могут не соответствовать предпочтениям пользователя. [Workflow и состав](https://github.com/obra/superpowers).

Skills.sh ранжирует по данным установок CLI. Популярность помогает найти кандидатов,
но не измеряет качество на нашей сцене, модели или игре; сам каталог не гарантирует
качество и безопасность всех пакетов. [Как устроен рейтинг](https://skills.sh/docs).

## Что проверять в кандидате

1. **Задача и результат.** Есть ли конкретный полезный сценарий, артефакт и критерий
   приёмки? Длинный текст и уверенный стиль сами по себе ничего не доказывают.
2. **Происхождение.** Автор или профильная команда, исходники, лицензия, история
   изменений, исправленные ошибки и совместимость с фактическими версиями.
3. **Исполнение.** Реальные команды/API, ясные зависимости, примеры, проверяемые
   ошибки и восстановление. Проверять не только README, но и scripts/hooks.
4. **Управление агентом.** Чёткие триггеры, небольшое ядро, загрузка справочников по
   необходимости, отсутствие конфликтов и скрытых внешних действий.
5. **Стоимость поддержки.** Новые сервисы, модельные веса, подписки, сроки обновления,
   нагрузка на контекст и GPU. Малый выигрыш не оправдывает большой новый стек.
6. **Сравнение.** Одинаковая задача, модель и входы; baseline без кандидата; несколько
   запусков там, где результат стохастический; оценка выхода без знания варианта.

## Небольшая очередь кандидатов

| Очередь | Кандидат | Проверка перед принятием |
|---|---|---|
| 1 | Наш общий набор evals + методы отладки Superpowers | Один воспроизводимый баг и одна регрессия; измерить исправление и число лишних действий |
| 2 | mcp-builder из Anthropic | Маленький локальный инструмент с проверяемыми входами, ошибками и обратным чтением результата |
| 3 | Remotion: markup/captions/render | 15–30 секунд титров с русским текстом, точным таймингом и обновлением данных |
| 4 | Vercel web-design-guidelines | Проверить реальную панель/сайт по клавиатуре, фокусу, переполнению и производительности |
| 5 | algorithmic-art из Anthropic | Сравнить подход с нашим formula-driven-production на задаче процедурного изображения |

Это очередь для отбора, не распоряжение устанавливать всё сразу. Для редких задач
Blender, Godot, DSP или конкретной видеомодели ищите прежде всего документацию
самого инструмента и технический первоисточник; готовый навык может оказаться слабее
небольшого собственного навыка, проверенного на реальном проекте.

## Что сохранять после проверки

Точный URL и commit, условия использования, выбранные файлы, адаптацию к модели и
инструментам, входные задачи, результаты baseline/кандидата, стоимость, дефекты,
решение «отклонён / проба / принят» и следующую дату проверки при изменении версий.
Без эксперимента кандидат остаётся кандидатом.
